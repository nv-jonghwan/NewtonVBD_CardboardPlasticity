# 복구 후 속도 확인과 보수적 튜닝

## 속도 저하 확인

복구된 원래 장면의 현재 GUI 실행은 16초 동작에 335.35초가 걸렸다. 이전 최적화 GUI는 약 191–192초, 제외한 재료 튜닝 GUI는 195.30초였다. 다만 서로 다른 재료의 실행 시간은 물리 상태와 정착 시점까지 달라 직접적인 성능 비교 기준이 될 수 없다.

원래 장면의 기존 guarded 기록과 현재 실행을 비교하면 계산 모드 프레임 수는 각각 active/supported/sleep = 556/226/178, 557/225/178로 거의 같다. 집기·상승·압착 시간은 16.76/17.57/29.07초에서 30.66/32.02/52.88초로 증가했다. 계산 예산이 늘어난 현상은 아니다. GPU 1에서 다른 프로젝트 프로세스와 이 프로젝트 Newton 작업이 동시에 상당한 SM 점유율을 보였다. GPU 공유 부하가 주요 원인으로 판단되며, 다른 프로젝트 프로세스는 변경하지 않았다.

같은 원래 장면을 GPU 0에서 새로 실행하면 256.57초였다. GPU 0에도 두 GUI의 렌더링 부하가 있으므로 무부하 벤치마크는 아니다. 이 실행은 15개 동작 검사 중 기존 정착 속도 기준(<10mm/s)만 실패했고, 집기·상승·압착·해제 및 관절 연결 검사를 통과했다. 최종 속도 30.22mm/s, 관절 최대 연결 오차 0.932mm. 기존과 새 기준 실행의 압착 시점 형상 정렬 RMS 차이는 2.52mm였다.

원래 설정 복구 직후의 별도 GUI 실행은 114.76초였지만 낙하 후 13.12초부터 sleep에 들어갔다. 늦게까지 변형이 남는 실행과 전체 시간만 비교하면 GPU 부하와 물리적 정착 차이가 섞인다. 따라서 이를 안정적인 속도 기준으로 사용하지 않는다.

## 결과 보존을 우선하는 변경

- GUI의 표시 갱신 상한을 30fps로 설정하는 `--max-fps` 옵션을 추가했다. 물리 worker는 별도 프로세스로 기존 고정 시간 간격과 solver 예산을 계속 사용한다. 표시만 제한하며 기록 재생은 경과 시간으로 진행한다.
- 기본 원본 장면은 보존한다. 첫 후보는 `graspForce`만 250→160으로 변경한다. 이 값은 실제 접촉력의 엄격한 상한이 아니라 구동 기준이다.
- 두 번째 후보는 위 힘 조정에 굽힘 MD/CD 1.5배만 추가한다. 항복곡률·손상률·경화비·잔류 강성·막 강성·두께·질량·마찰·메시·충돌체·최종 압착 기준 4000은 유지한다. 굽힘 계수 증가는 절대 항복 모멘트와 비례 감쇠에도 영향을 주므로 완전히 같은 재료라고 주장하지 않는다.
- 후보별 모든 USD 속성과 관계를 원본과 비교하여 각각 선언한 1개/3개 속성만 달라졌음을 확인했다. solver 코드는 변경하지 않았다.

## 검증 기준과 상태

처짐 깊이·손가락 간격 외에 같은 시점/시선/배율의 물리 메시를 확인하고, 판면 내부 15도 초과 굽힘 모서리 수, 굽힘각 95백분위, 전체 소성 힌지 수와 소성 일을 비교한다. 원래 박스의 90도 모서리는 판면 내부 주름 집계에서 제외한다. 이 지표는 형태 비교를 돕는 진단이며 사용자 시각 평가나 실험적 재료 검증을 대신하지 않는다.

기존에 제외한 후보는 압착 시점 판면 내부 15도 초과 모서리가 1,818개였다. 새 원래 장면 기준은 804개였다. 기존 후보는 처짐만 맞고 판면 주름 분포는 크게 달랐다는 것을 별도로 확인했다.

두 후보 모두 전체 시퀀스 평가를 완료했다. **이번 GUI 검토 후보는 재료를 바꾸지 않은 force160이다.** 초기 처짐 1mm 및 집기 변형 절반 목표를 달성했다고 주장하지 않는다.

증거: `outputs/conservative_tuning/speed_audit.json`, `baseline_review/`, 각 후보의 `asset_validation.json`, 전체 실행 기록. 새 비교 도구: `scripts/review_conservative_tuning.py`.

선택 후보의 압착/최종 메시 정렬 RMS는 2.99/3.52mm, 강성 후보는 6.36/8.50mm다. 앞·뒤에서 물리 메시를 비교했고 선택 후보는 원래 넓은 판면과 큰 접힘을 대체로 보존했다. 시각적 차이가 전혀 없다는 뜻은 아니다. 강성 후보는 최종 속도 76.1mm/s 및 관절 연결 오차 1.960mm로, 선택 후보의 31.0mm/s 및 1.078mm보다 여유가 작아 적용하지 않았다.

기준과 두 후보 모두 동작 검사 14/15 통과, 기존 정착 기준 실패는 그대로 보고한다. 재료 상태 유한성·소성 일 단조성·손상 범위·소성 이력·접촉 overflow 없음 확인. 힘 명령 회귀 검사 2개 통과. GUI의 30fps 표시/GPU 0 설정에서 0.25초 Play/Pause/Reset 검사 통과 및 정상 종료를 확인했다. 후보 benchmark 237.58/239.14초는 공유 GPU 관측이며 재료 변경에 의한 가속으로 해석하지 않는다. 30fps 표시 제한만의 독립적 속도 향상률은 측정하지 않았다.

검토용 GUI는 아래 명령으로 연다. 원래 primitive 장면의 기본 선택은 그대로이며 현재 창에만 선택 후보와 GPU 0을 명시했다. 표시 30fps는 물리 실시간 30fps를 의미하지 않는다.

```bash

  --physics-device cuda:0 --max-fps 30
```

초기 자중 처짐은 약14.5mm로 남아 있다. 현재 첫 단계는 원래 형태 보존을 우선하여 집기/상승 중의 과도한 처짐을 일부 줄인 결과다. 나머지 목표를 맞추려고 항복·손상값을 다시 크게 바꾸거나 압착 형태의 보존을 희생하지 않는다.

데스크톱 GUI PID145304/window0x480000d에서 선택 후보/GPU0/guarded/유한3458정점 및17강체를 확인했다. 실제 재생은12.283초까지 관찰됐고 이후 exit_code0으로 정상 종료됐다. 종료 시점에 원래 창117317도 닫혀 있었으며 현재 GUI는 열려 있지 않다. 새 GUI에서 전체16초 실행 시간을 측정했다고 주장하지 않는다. 전체동작 수치는 별도의 완료된 benchmark를 사용한다.
