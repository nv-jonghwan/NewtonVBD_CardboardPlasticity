# 압착 후 추가 오므라듦 수정: 접힌 힌지의 각도 저항

압착 후에도 계속 오므라들던 동작을 줄이기 위해, 영구 접힘이 생긴 힌지에 회전 마찰 형태의 저항을 추가했다. 재료 강성·손상 계수만 바꾼 이전 실험과 달리, 남아 있는 내부 응력 때문에 접힘각이 계속 움직이는 경로에 직접 소산 저항을 둔다. 물리 프로필은 두 GPU의 독립 전체 동작에서 검증했으며, GUI에서도 재확인한다.

## 원인 분리

`outputs/crease_friction/checkpoint12`에 저장한 동일 압착 형상·소성 이력에서 시작해 중력, 그리퍼/테이블 접촉, 초기 속도를 제거했다. 자체 접촉과 내부 탄성력은 유지했다. 이는 숨겨진 접촉 승수까지 복원한 전체 장면의 재시작이 아니라, 동일 조건의 독립 cold-start 제하 실험이다.

기존 소성 갱신을 유지하면2초 동안 폐곡면 부피 지표32.6~39.7%, 외곽 부피27.5~28.6%가 줄었다. 진단 목적으로 소성 갱신만 끈 경우에도 폐곡면 부피8.7~18.2%, 외곽 부피9.5~10.0%가 줄었다. 따라서 낙하 충격이나 소성 갱신만으로 설명할 수 없으며 압착 상태의 잔류 응력에 따른 형상 변화도 존재한다. 이 제하 실험의 서브스텝 계측에서는 탄성각이π를 넘는 경우가 없었다. 이를 다른 모든 동작의 분기각 안전성 증명으로 일반화하지 않는다.

## 저항 법칙

힌지의 이전 서브스텝 각도와 현재 각도의 차이를 `delta`, 누적 소성각을 `alpha`, 힌지 폭을 `h`라 두면:

```
activation = 1 - exp(-alpha / (5*h))
limit = damaged_bending_stiffness * edge_length * h * friction_curvature
effective_limit = activation * limit
epsilon = dt * 0.005  # rad, angular slip rate regularization
moment = effective_limit * clamp(delta / epsilon, -1, 1)
```

이 모멘트는 각도 변화의 반대 방향으로 작용한다. 소성 이력이 없는 평평한 힌지에는 추가 저항이 없고, 접힌 힌지는 더 큰 하중이 오면 한계 모멘트를 넘어 계속 움직인다. 기존 소성 rest angle을 지우거나 현재 형상으로 덮어쓰지 않는다. 하중·시각별 강제 고정, 부피 보존 투영, 렌더링을 통한 수축 은폐도 사용하지 않는다.

힘은 Huber 정규화된 `limit*abs(delta)` 소산 퍼텐셜의 음의 기울기다. 바깥 구간의 정확한 이차 미분0을 그대로 쓴 첫 구현은 정지각을 넘나드는 갱신과 큰 속도를 보였다. 양의 이차 상계 `limit/max(abs(delta),epsilon)`를 근사 접선으로 사용하도록 수정해 이를 억제했다. 이는 힘을 바꾸는 보정이 아니라, 동일 소산 퍼텐셜을 안정적으로 푸는 갱신 행렬이다.

GPU의 full/local VBD, full/representative ROM에 같은 법칙을 적용한다. 별도 `crease_friction_work_J`는 각 서브스텝의 `moment*delta`를 합산한 비음수 후진 Euler 마찰 일이며 기존 소성 일과 구분한다. CUDA graph 내부에서 처리하고, 기존 프레임 telemetry만 CPU로 읽는다.

## 선택 설정과 검증

선택한 `--crease-friction-curvature 45`는 기존4mm/S16/24회 ROM-VBD 혼합 설정에 추가한다. 이전에 실패한 점진 연화(memory150), 강성 하한45%, 경화0.2, 손상 속도 변경은 채택하지 않았다. 실물 시험으로 보정한 회전 마찰 계수는 아니며, 현재 장면의 원하는 접힘 유지 거동을 위한 모델 확장이다.

동일 형상의2초 제하 실험에서 이 설정은 폐곡면 부피+0.74%, 외곽 부피−0.34%로 형상을 유지했다. 추가 누적 소성각 합은 기존1275.7rad에서18.7rad로 줄었다(4200힌지의 합계이며 단일 힌지 각도가 아니다).

전체20초 동작 결과:

| 실행 |12→16초 부피 지표|12→16초 외곽 부피|낙하 후 정지 진입|
|---|---:|---:|---:|
|이전 기준24회|−17.95%|−15.31%|16초까지 정지하지 않음|
|새 설정 GPU1|+5.89%|+2.70%|16.983초|
|새 설정 GPU0|+9.21%|+4.74%|17.567초|

두 실행 모두18~20초 정지 상태를 유지했다. 정지는 기존의 지지 조건·모든 정점의 속도/변위 연속 구간 검사로 결정되며, 특정 시각에 켜지도록 바꾸지 않았다. 하중이 가해지는 집기 구간에는 잠들지 않는다. 설정15는 제하 실험에서는 개선됐지만 전체 낙하 후20초까지 약35% 추가 수축해 채택하지 않았다.

파지는 두 실행 모두 전체 보유 구간, 해제 전 테이블 복귀 없음, 양쪽 접촉, 양쪽 손끝 기하학적 관여의4개 기준을 통과했다. 기존20mm 재료점 이동 한계는 통과하지 못했으므로 무슬립을 주장하지 않는다.12초의 손가락 간격은 약148mm로 이전 약141mm보다7mm 더 남는다. 강한 압착과 영구 접힘은 유지되지만 작은 주름 수와 최종 형태는 변한다. 비교 그림은 `outputs/crease_friction/shape_review/solver_shapes.png`에 있다.

91개 회귀 검사 통과: 소산력의 에너지 기울기 일치, 양의 상계, 운동량 균형, 모멘트 상한, 비음수 일/정지 시 무소산, 저항을 켠 ROM·대표 요소·국부 Jacobi의 일치, 기존 물성/접촉/렌더링/휴면 검사. 로그 `outputs/crease_friction/regression_final.log`.

GPU1의16초 계산은81.40초로 이전 GPU1 기준80.65초와 비슷했다. GPU0는101.28초였다. 공유 GPU와 다른 실행 부하가 있어 이 숫자로 일반적인 속도 차이를 단정하지 않는다.

## 실행

```
bash scripts/live_crease_friction.sh
```

새 설정의 라이브 계산과 동일 설정의 Recorded replay를 제공한다. 전체 라이브 궤적을 남기려면 고유한 `--record-directory`를 지정한다. 기존 실행기는 비교·복구를 위해 보존했다.

## 실제 GUI 전체 동작 재검증

새 데스크톱 GUI PID445986/window0x300000d에서20초를 새로 계산했다. 실제 worker의4mm/S16/24회/힌지 저항45 및1402개 유한 정점을 확인했다.12→16초 폐곡면 부피+7.23%, 외곽 부피+3.45%;12→20초 폐곡면 부피+7.13%로 추가 수축 대신 소량 복원됐다. 낙하 후19.783초에 기존 지지/정지 기준을 만족했으며20초의 최대 속도는0이었다. 파지 기준4/5와 하중 중 휴면 없음도 확인했다.

마찰 일28.7047J는 전 구간 단조 증가했고, 힌지별 비음수 및CSV합계/최종GPU배열 합계 일치를 확인했다. 물성 유한성·소성 이력·손상 범위·소성 일 검사도 모두 통과했다. 프레임당 에너지 계측은 힘이나 rest angle을 수정하지 않는다. 전체 라이브20초 계산141.07초이며 GUI/공유GPU 부하를 포함한다.

실제 라이브 기록은 `outputs/crease_friction/live_gui`에 보관했다. `state.csv`는 worker의 원본 `state-445986.csv` 복사본이며, `performance.json`은 완료 worker telemetry에서 추출한 값이다. 기존 GUI410405를 정상 종료하고 새 GUI를 표시했다. Play/Pause/Reset 및 Recorded replay Pause/Resume/최종 프레임 검사는 별도의 headless GUI445107에서 통과했다.

이번 동작의 추가 오므라듦 수정은 구현·반복·라이브 검증까지 완료했다. 실물 재료 보정, 다른 하중/격자로의 일반화, 엄격한20mm 무슬립 기준은 별도 검증 범위다.
