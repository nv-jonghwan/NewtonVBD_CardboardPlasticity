# 고해상도 유지 계산 최적화

사용자 요청: 해상도를 낮추지 않고 실제 물리 계산과 화면 갱신 속도를 개선한다.

## 유지한 조건

- 물리 정점 3,458개, 삼각형 6,912개, 굽힘 힌지 10,368개.
- 표시 정점 521,280개, 표시 삼각형 173,760개.
- 15 mm 두께, 질량, 막/굽힘 강성, 국부 주름/손상식, 감쇠, Robotiq 구동값.
- 프레임당 32 substeps × 32 VBD iterations, 자체 충돌/강체 접촉/관통 방지.
- 장면 USD 및 원본 자산은 변경하지 않았다. 기존 결과는 검증 완료 후에도 보존한다.

## 계산 변경

1. **자체 충돌 목록 압축**: 기존 BVH가 접촉 버퍼에 저장한 모든 edge-edge 및 vertex-triangle 후보를 GPU 배열에 모은다. 매 반복마다 primitive별 가변 길이 목록을 다시 순회하는 대신, 후보 쌍을 GPU 스레드에 분배한다. 기존 후보 용량과 제외 기준을 그대로 사용하며 접촉 에너지와 관통 방지 평면 함수도 Newton 원본을 호출한다.
2. **기존 반복 순서 유지**: 원래 8개 색상 그룹과 Gauss-Seidel 순서를 유지한다. 7개 그룹 후보는 빠르지만 압착 중 되튐이 증가하여 채택하지 않았다.
3. **평행이동 보정 합산**: 수천 스레드가 하나의 전역 합계에 동시에 쓰던 방식을 블록 내 reduction과 32개 부분합으로 바꾼다. 보정용 3×3 역행렬은 반복당 한 번 계산하고 모든 정점에 공유한다. 같은 관성·접촉 에너지와 보정 한도를 사용한다.
4. **표시 곡면**: 고정 보간 계수를 희소 행렬로 미리 구성하고, 정점마다 큰 중간 배열을 복사하는 비용을 줄인다. 에지 집계도 사전 계산한 인덱스와 `bincount`를 쓴다. 삼각형 수, UV, 주름 조건, 두께 보간, float64 계산/float32 출력은 유지한다.

기존 creaseDamageLength 재료를 쓰는 `robotiq-creased` 계열에 새 물리 overlay를 적용한다. 그 외 모드는 보존한 `legacy_block_solver.py`를 사용한다. 표시 보간 최적화는 모든 모드에 적용된다.

공유 Newton/Warp 설치는 변경하지 않았다. 프로젝트 내부의 Newton 1.6 전용 overlay이며, 원본 코드 라이선스는 `third_party/`에 보존했다.

## 검증 방법

- 초기/압착/최종 상태에서 원본 충돌 후보와 압축 목록을 정렬 비교하여 누락·중복 검출.
- 모든 색상에서 원본 Newton 힘/Hessian과 비교. 합산 순서에 따른 float32 반올림 오차를 허용하되 최대 성분 대비 오차 1e-5 미만을 요구한다.
- 관통 방지 truncation 계수 비교: 절대 오차 1e-6 미만.
- 관성 평행이동 보정을 독립적인 NumPy float64 계산과 비교.
- 동일 상태의 표시 정점/법선 비교: 각각 절대 오차 1e-7 m / 1e-6 미만.
- 전체 시퀀스는 기존 15개 접촉·링크·안착 기준, 13개 주름·진동 비교 기준을 그대로 적용한다.

부동소수점 합산 순서가 바뀌므로 전체 비선형 접힘 궤적의 비트 단위 동일성을 보장하지 않는다. 같은 물성과 해상도에서 주름/접촉/진동 품질을 별도로 재검증한다.

## 측정 기록

동일 장면, GPU, warm-up 3프레임 후 12프레임 측정: `outputs/optimization/profile_before.json`, `profile_final.json`. 단일 eager substep의 CUDA 이벤트 측정은 병목 분석용이며, 이벤트 계측 비용이 있어 graph 전체 처리 시간과 구분한다.

최종 8색상 버전의 전체16초 동작은 **393.904초(6.57분)**에 완료했다. 기존623.441초(10.39분) 대비 **1.583배**, 계산 시간 **36.82% 감소**다. 전체 worker 시간에는 각 프레임 진단과 snapshot 저장을 포함하며, 활성 루프 이전의 모델 준비는 제외한다.

곡면 계산은1.728배 빨라졌고21개 프레임의 float32 표시 정점·법선 배열은 전후 정확히 같았다. 이 시간에는 USD 갱신이나 RTX 렌더링이 포함되지 않으므로 전체 화면 FPS가1.728배라는 뜻은 아니다. 새 물리 계산은 아직 실시간이 아니며, 저장된 Recorded replay는16초 재생이다.

28개 회귀/구성식/형상 검사,64개 커널·목록·보간 동등성 검사, 기존15개 전체 동작 기준과13개 주름·진동 비교 기준이 모두 통과했다. 힘/Hessian 최대 성분 대비 차이는최대3.20e-6, truncation 계수 차이는최대5.96e-8이었다.

## 채택하지 않은 후보

7개 색상 그룹은 모든 에너지 stencil의 독립성을 만족했고, 16초 전체 동작을367.826초에 계산했다. 그러나 순차 비선형 갱신 순서 변화로 압착 중 판면 움직임6.138mm/s, 손가락 재벌어짐4.506mm, 판면 역방향 경로1.236mm가 되어 기존 주름/진동 비교의3개 기준을 실패했다.15개 동작 기준은 통과했으나 이 결과를 최종 재생으로 승격하지 않았다. `outputs/robotiq_optimized_seven_colors_trial/`에 실패 판정을 그대로 보존했다.

작은 GPU launch grid(2,048 threads)로 자체 충돌 쌍을 처리한 후보는 오히려 느려져 제외했다. 색상별 추가 충돌 목록 및 별도 강체 접촉 순회 최적화도 전체 처리 시간 이득이 없어 제외했다.

## GUI와 최종 결과

0.3초 새 물리 계산의 Play/Pause/Reset과 전체16초 Recorded replay의 일시정지·재개·최종 프레임 표시를 통과했다. 실제 GUI 압착/안착 캡처를 확인한 뒤 검증된 기록을 `outputs/robotiq_creased/`에 반영했다. 이전 결과는 `outputs/robotiq_creased_before_optimization/`, 원래 후보는 `outputs/robotiq_optimized/`에 남겼다. 새 창은 기존과 같은 `--quality robotiq-creased`로 실행한다.

![최적화 결과의 안착 화면](../outputs/robotiq_creased/gui_settled.png)

`outputs/optimization/gui_test.log`가 GUI 검증 기록이다. `live_performance.json`은0.3초 제어 시험 값이므로 전체16초 물리 처리 시간으로 해석하지 않는다. 전체 처리 시간은 `validation.json`과 최적화 `report.json`을 사용한다.
