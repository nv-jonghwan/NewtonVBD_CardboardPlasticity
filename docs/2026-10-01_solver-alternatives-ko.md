# 해상도를 유지한 계산 방식 변경 검토

현재 10 mm 검토 장면의 새 물리 계산은 GUI 로그에서 16초 동작당 139.6–161.5초였다. 반복 재생과 새 조건의 계산은 구분해야 한다. 이번 검토에서는 더 빠른 새 물리 계산을 우선한다고 가정했다.

## 현재 장면 실측

`scripts/profile_creased_cost.py`에 장면/궤적 경로 인자를 추가하고 `demo_scene_robotiq_board10_support20_trial.usda`의 초기 안정화 구간 12프레임을 측정했다. 결과는 `outputs/optimization/profile_board10_initial.json`에 있다.

- 프레임 전체 평균 138.14 ms, 동기화한 GPU 그래프 중앙값 134.51 ms. 서로 다른 통계이지만 물리 GPU 실행이 주된 비용이라는 근거다.
- 표시 표면 평가는 별도 측정으로 중앙값 28.92 ms이며 위 프레임 전체 값에 포함되지 않는다. GUI 동시 실행의 총 지연과 단순 합산하지 않는다.
- 물리 정점 3,458개, 삼각형 6,912개, 표시 삼각형 173,760개 유지. 프로파일의 render_vertices=521,280은 삼각형별 출력 정점 수다.
- 활성 모드는 프레임당 16 substeps, 각 substep에서 강체 48회 / 종이 17회 반복한다.
- CUDA 그래프 밖의 별도 한 substep 커널 계측에서는 강체 해석, 강체별 접촉 누적, 관절/접촉 dual 갱신의 합이 5.709 ms / 전체 12.300 ms, 약 46.4%였다. 계측/dispatch 오버헤드가 있는 초기 상태의 귀속 측정이며, 압착 구간이나 전체 실행의 비율로 일반화하지 않는다.
- 기존 기록의 960개 프레임은 active 557 / supported 147 / sleep 256이었다. supported 모드는 32 substeps × 종이 48회로 활성 모드보다 종이 반복 횟수가 약 5.65배 많다. 147프레임이 같은 시간 비중을 차지한다는 뜻은 아니다.

현재 실측으로 GUI 최적화만으로 새 물리 계산을 실시간화할 수 있다는 근거는 없다. 그리퍼 비용을 전부 없애더라도 종이 계산이 남으므로, 이 한 구간의 계측으로 수십 배 가속을 약속해서도 안 된다.

## 추천: 관절 전용 계산기와 종이 계산기의 결합

Newton 1.6 설치 소스의 `examples/multiphysics/example_mujoco_vbd_coupled_solver.py`는 MuJoCo 또는 Kamino 강체 계산과 VBD 변형체 계산을 `SolverCoupledProxy`로 결합한다. 분리한 계산기 사이에 접촉 반응을 전달하는 방식이다. [Newton 공식 결합 설명](https://newton-physics.github.io/newton/1.5.0/concepts/coupling.html)은 1.5 문서이므로 실제 API 확인은 설치된 1.6 소스를 기준으로 했다.

현재 Robotiq는 닫힌 관절 루프를 포함한다. 설치된 SolverMuJoCo 소스는 revolute/ball loop closure 변환, equality/mimic 제약과 joint_f/target 제어를 지원한다. 따라서 조사할 가치가 있지만, 현재 장면이 변환·연동 검증을 통과했다는 뜻은 아니다. 현재 Python 환경에 `mujoco`와 `mujoco_warp`는 설치되어 있지 않다.

시험 구현에서는 다음을 유지해야 한다.

1. 같은 물리/표시 해상도, 재료, 소성 이력과 자기접촉.
2. 동적인 손가락과 접촉 반력의 양방향 전달. 손가락 궤적을 강제로 재생하는 방식과 구분한다.
3. 기존 관절 오차, 파지/들기/압착/해제, 영구 주름, 정지 판정 기준.
4. 현재 GUI/공유 도구 체계를 유지하고 별도 실험 환경과 출력 사용.

주요 구현 점검 대상은 처방된 UR 팔과 동적 그리퍼의 경계, 닫힌 관절 루프, 접촉 강성/마찰의 전달, VBD model view에서 소성 rest angle과 stiffness 갱신 공유, 기존 custom state 복사 및 GPU 그래프 캡처다. 결합 반복 비용과 새 오차가 생길 수 있으므로 먼저 동일 장면의 부분 구간을 비교하고, 그다음 16초 전체 실행을 검증해야 한다. 속도 이득은 아직 미측정이다.

## 다른 선택지의 한계

- **XPBD 변경:** 설치 소스의 제약 구성은 현재 삼각형 막 에너지와 자기접촉 구현의 직접 대체가 아니다. 강한 압착에서 신장/접촉/소성 보정과 재검증이 필요하므로 우선순위가 낮다.
- **큰 시간 간격의 준정적 계산:** 천천히 누르는 구간에는 검토할 수 있지만, 들기·놓기·충돌까지 같은 방식으로 처리하면 동역학이 달라진다. 현재 전체 시퀀스의 즉시 대체가 아니다.
- **축소 모델:** 표시 해상도를 유지할 수 있어도 물리 자유도가 감소한다. 물리 해상도 유지 조건을 만족했다고 설명해서는 안 된다.
- **기록 재생:** 동일 결과를 빠르게 확인할 수 있지만 힘·위치 변경에 대한 새 계산을 빠르게 만들지는 않는다.

이번 작업은 현재 병목의 재측정과 대체 방식의 소스 수준 검토까지 완료했다. 새로운 결합 계산기는 구현/검증하지 않았고 장면·재료·GUI·기존 결과를 바꾸지 않았다. 현재 10 mm 후보의 post-14s 정지 기준 미통과도 그대로 남아 있다.
